# «Тандем» · хакатон MAX, трек «Эффективный бизнес»

Бот для центров карьеры вузов в MAX с мини-приложением: малый бизнес получает практиканта под задачу, а студент — только
подходящие места.

## Назначение

Владелец малой компании за 3 минуты публикует место для практики, стажировки или подработки. Бот доставляет его
только тем студентам, кому оно подходит по навыкам, формату и городу. Работодатель видит список заинтересованных
студентов с процентом совпадения и расшифровкой. После взаимного интереса обе стороны сразу получают контакты и
чек-лист документов практики.

**Проблема по формуле кейса.** Владелец малой компании без HR, которому нужен человек на сайт, аналитику,
маркетплейсы или 1С, хочет взять практиканта из вуза, но не знает, как выйти на студентов и какие документы оформить.
Из-за этого задача остаётся несделанной или студент работает неофициально, и практику ему не засчитывают.

**Пользователи.** Основной — работодатель из малого бизнеса, которому на сезон нужны 2–3 практиканта или стажёра.
Вторая сторона — студент. Центр карьеры вуза — канал и оператор; пилот предлагаем центру карьеры РАНХиГС.
Направление кейса — «Кадры для бизнеса и сельского хозяйства».

## Основной пользовательский сценарий

1. **Работодатель** открывает бота → «Я работодатель» → согласие на обработку данных → профиль компании: название,
   город, контактное лицо.
2. **Карточка места за 8 шагов:**
   - задача и тег задачи — тег подставляет навыки;
   - тип места: практика, стажировка или подработка;
   - обязательные и желательные навыки;
   - формат и город;
   - сроки, оплата, число мест.
   
   Затем превью «как у студента» → «Опубликовать». Время сборки карточки видно на экране публикации.
3. **Подбор.** Сервер считает совпадение с анкетами студентов. Тем, у кого совпадение от 60 %, бот присылает
   место: не больше 3 в сутки, с 9:00 до 22:00.
4. **Студент** один раз заполняет анкету: вуз, направление, курс, город, формат, навыки. В колоде мест он видит
   карточки по убыванию совпадения и откликается свайпом вправо — «Интересно».
5. **Работодатель** получает от бота сообщение о новом кандидате. В мини-приложении он видит заинтересованных
   с процентом и расшифровкой навыков, сравнивает их и приглашает или отказывает кнопкой; на отмену — 5 секунд.
6. **«Это тандем!»** После приглашения студент получает контакт компании и чек-лист документов практики,
   работодатель — фамилию и телефон студента. Бот дублирует это в чат.

**Результат:** у работодателя — подходящий практикант и понятный список документов, у студента — подходящее место
и следующие шаги. Проверка всего сценария одним аккаунтом — в разделе
[«Пошаговый сценарий проверки»](#пошаговый-сценарий-проверки).

## Состав и архитектура

| Компонент | Что делает | Технологии | Где |
|---|---|---|---|
| Мини-приложение | экраны студента и работодателя внутри MAX | React, TypeScript, Vite, MAX UI, MAX Bridge | `apps/miniapp/`, контейнер `meb-miniapp` — статика за nginx |
| Сервер | API мини-приложения и бот в одном процессе | Node.js 24, TypeScript, Express 5, TypeORM | `apps/server/` |
| БД | пользователи, анкеты, места, отклики, уведомления, справочники | PostgreSQL 18 | том `db-data` |
| Прокси (прод) | HTTPS, маршрутизация: свой Caddy (`compose.prod.yaml`) или уже работающий на сервере nginx/Caddy (`compose.proxy.yaml`) | Caddy 2 / nginx | `deploy/` |

```
MAX (клиент) ──> мини-приложение ──HTTPS /api──> server ──> PostgreSQL
                                                   │  ▲
MAX Bot API  <── уведомления ── модуль bot <─ события ┘  └── вебхук /bot/webhook <── MAX Bot API
```

Внутри сервера модули разделены: `api` (маршруты, права), `auth` (проверка подписи MAX), `db` (схема и миграции),
`matching` (расчёт совпадения, чистые функции), `bot` (MAX Bot API и очередь уведомлений). API публикует внутренние
события (`internship.created`, `interest.created`, `interest.invited`), бот на них подписан: API ничего не знает про
Bot API, бот — про HTTP. Модуль `seed` при старте грузит справочники навыков и тегов задач, а при `SEED_DEMO=true` —
тестовые данные. Схемы компонентов, сценария и данных — [docs/architecture.md](docs/architecture.md), контракт API —
[docs/api.md](docs/api.md), деплой — [docs/deploy.md](docs/deploy.md).

Сервер — внутренний бэкенд мини-приложения: без подписи MAX его не вызвать. Собственный публичный API не заявляем,
поэтому OpenAPI и `DATA-API.yaml` не прикладываем.

### Расчёт совпадения

Модуль [`matching`](apps/server/src/matching/match.ts) — чистые функции без БД и сети, покрыты юнит-тестами.
Никакого ИИ: работодатель видит, из чего сложился процент.

1. **Жёсткие фильтры.** Студенту должен подходить формат работы (очно, гибрид, удалённо). Для очных и гибридных
   стажировок город студента должен совпадать с городом стажировки. Город в анкете — свободный текст, поэтому
   регистр, лишние пробелы, «ё», приставка «г.», регион или страна через запятую («Казань, Татарстан»,
   «Москва, Россия») и сокращения городов пилота («Мск», «СПб», «Питер») не мешают.
   Не прошёл фильтр — стажировка не показывается в ленте и не присылается ботом.
2. **Процент:** `70 % × доля закрытых обязательных навыков + 30 % × доля закрытых желательных`.
   Нет желательных — считаются только обязательные; нет обязательных — только желательные. Навыки сравниваются
   только по справочнику, свободный текст не участвует. Округление до целого, половина — вверх.
3. **Расшифровка** всегда идёт вместе с процентом: какие обязательные и желательные навыки закрыты, какие нет.
4. **Уведомление бота** приходит, только если процент не ниже `MATCH_NOTIFY_THRESHOLD` (по умолчанию 60 %) **и**
   закрыты все обязательные навыки. Иначе студент без одного обязательного, но со всеми желательными получал бы
   35 + 30 = 65 % и уведомление. В ленте такие места остаются — студент может решить сам.
5. **Порядок ленты:** по проценту; при равном проценте выше места, где закрыты все обязательные навыки, затем те,
   что подходят по месяцу практики из анкеты; дальше — сначала новые. Сам процент от этого не меняется.

**Пример из тестовых данных.** Стажировка «Стажёр-аналитик продаж»: обязательные — Excel, SQL; желательные —
Power BI, Статистика. Студент знает Excel, SQL, Power BI, Google Таблицы.
Обязательные закрыты 2 из 2, желательные 1 из 2: `70 × 2/2 + 30 × 1/2 = 85 %`.

```json
{ "score": 85, "mustMatched": ["excel", "sql"], "mustMissing": [], "niceMatched": ["power_bi"], "niceMissing": ["statistics"] }
```

### Бот

Модуль [`bot`](apps/server/src/bot/) работает в том же процессе, что и API.

- **`/start`** — приветствие и две кнопки `open_app`: «Я студент» и «Я работодатель». Они открывают мини-приложение
  с параметром запуска `student` или `employer`. Диплинк `https://max.ru/<ник_бота>?start=internship_<id>`
  добавляет кнопку «Открыть стажировку». На любое другое сообщение бот отвечает подсказкой с теми же кнопками —
  тупиков в диалоге нет. В группах и на сообщения других ботов бот молчит.
- **Уведомления по событиям:**

  | Событие | Кому | Что |
  |---|---|---|
  | опубликовано место | студентам, прошедшим фильтры, с совпадением от порога и всеми обязательными навыками | название, компания, тип и оплата («Стажировка · 30 000 ₽ в месяц»), процент, до трёх совпавших навыков, кнопка «Смотреть» |
  | студент нажал «Интересно» | владельцу стажировки | «новый заинтересованный студент», процент, кнопка «Кандидаты» |
  | работодатель пригласил | студенту | контакт работодателя и чек-лист: для практики — направление, договор о практической подготовке (приказ № 885/390), задание, отзыв; для стажировки и подработки — задачи, график, оплата, оформление |
  | работодатель пригласил | работодателю | имя и телефон студента |

- **Очередь отправки** в таблице `notifications`. Все сообщения, включая ответ на `/start`, идут через неё:
  - лимиты MAX: не больше 2 сообщений в секунду в один диалог и 25 запросов в секунду всего (лимит платформы — 30);
  - временная ошибка (429, 5xx, сеть) — повтор с паузой 5, 10, 20… секунд, до 5 попыток;
    `403` (пользователь остановил бота) — без повторов;
  - у каждого уведомления ключ идемпотентности: повтор события или повторная доставка вебхука не присылают
    сообщение второй раз;
  - ошибка отправки не влияет на действие пользователя в мини-приложении: очередь работает отдельно от API;
  - в логи попадают только id и вид уведомления, без текста.
- **Не спамит:** студенту не больше 3 новых мест в сутки, остальные — одной подборкой со ссылкой на ленту;
  с 22:00 до 9:00 по Москве уведомления откладываются до утра. Ответ на `/start` и на сообщения приходит сразу.
- **Тестовым пользователям бот не пишет**: у них выдуманные id MAX.

### Возможности MAX и режим ярмарки вакансий

Что мини-приложение берёт от платформы, кроме запуска из бота:

| Возможность MAX | Зачем |
|---|---|
| Данные запуска `initData` | вход без регистрации: подпись проверяется на сервере на каждом запросе |
| `requestContact` | телефон, подтверждённый MAX, — одним нажатием, без ручного ввода |
| `openCodeReader` | сканер QR-кода места прямо в колоде студента |
| `shareMaxContent` | «Поделиться местом» с другом в MAX |
| Параметр `startapp` в ссылке | ссылка или QR сразу открывают карточку места |
| `BackButton`, `HapticFeedback` | системная кнопка «Назад» и тактильный отклик на решения |

**Режим ярмарки вакансий** — сценарий для карьерного форума:

1. У каждого открытого места есть QR-плакат для стенда. Его можно распечатать, показать на весь экран или отправить
   в MAX.
2. Студент сканирует код камерой внутри MAX или камерой телефона и сразу попадает в карточку места с процентом
   совпадения.
3. Если анкеты ещё нет, после согласия и анкеты студент возвращается на то же место. «Интересно» — и компания
   видит отклик в списке кандидатов.
4. Владелец, открывший ссылку на своё место, попадает к кандидатам. Кнопка «Посмотреть как студент» показывает
   место глазами студента.

**Как проверить сканер одним телефоном.** Второе устройство не нужно: сканер MAX читает QR и из картинки.

1. В «Моих местах» нажмите значок QR на плитке места → «На весь экран» и сохраните скриншот плаката.
2. «Сменить роль» → «Я студент» → в колоде мест нажмите сканер — значок QR справа от заголовка «Для вас».
3. В окне сканера выберите картинку из галереи — откроется карточка места с процентом совпадения.

## Запуск одной командой

```bash
cp .env.example .env    # заполнить MAX_BOT_TOKEN и POSTGRES_PASSWORD; если 3000/8080 заняты — поменять SERVER_PORT/MINIAPP_PORT
docker compose up --build
```

Для проверки на своей машине подойдёт любое непустое значение `MAX_BOT_TOKEN` (например, `local-check`) и любой
`POSTGRES_PASSWORD`: API, подпись данных запуска для smoke-проверки и тестовые данные работают, бот только не
отправит сообщений. Проверка в самом MAX — через нашего развёрнутого бота, токен для этого не нужен.

Поднимаются `db`, `meb-server` и `meb-miniapp`; при старте сервер применяет миграции, загружает справочники и (при
`SEED_DEMO=true`) тестовые данные. Мини-приложение отдаётся на `http://localhost:8080` (`MINIAPP_PORT`). В обычном
браузере оно покажет «Не получилось загрузить» — так и должно быть: статика в compose не проксирует `/api`, а API
принимает запросы только с подписью данных запуска MAX. Сценарий целиком проходится внутри MAX через развёрнутого
бота, локальный стек проверяет smoke-скрипт ниже. Проверка: `curl http://localhost:3000/api/health` (порт —
`SERVER_PORT` из `.env`) → `{"status":"ok","db":"ok"}` или полная smoke-проверка
`node --env-file=.env scripts/smoke.mjs` (мини-приложение и API; токен и порты берутся из `.env`; нужен Node.js 20.6+
на хосте; создаёт служебного пользователя «Smoke»).

**Бот локально на `/start` не отвечает:** входящие сообщения MAX доставляет только на вебхук по HTTPS на 443 при
заданном `MAX_WEBHOOK_SECRET`, то есть на развёрнутом сервере ([docs/deploy.md](docs/deploy.md)). Локально бот только
ставит уведомления в очередь и пытается их отправить.

Сборка и запуск с нуля всего стека — БД, сервер и мини-приложение (без скачивания базовых образов) — замеряются в CI
на каждом изменении, workflow `compose`: **38 с** при лимите 5 минут.

## Параметры окружения

- Docker Engine 24+ и Docker Compose v2.24+ (используется `!reset` в `compose.prod.yaml`).
- ОС: любая с Docker. Проверено на чистой машине: VPS с Ubuntu 24.04, Docker 29.8, Compose 5.5 — сборка и запуск
  прод-связки (`compose.yaml` + `compose.prod.yaml`) за 205 с, 29.09; в CI — на Ubuntu 24.04 на каждом изменении.
- Свободные порты 3000 и 8080 (меняются через `SERVER_PORT` и `MINIAPP_PORT`).
- Для smoke-проверки — Node.js 20.6+ на хосте (необязательно).
- Для прода — сервер с публичным IP, домен и открытые 80/443, см. [docs/deploy.md](docs/deploy.md).

## Внешние сервисы и интеграции

| Сервис | Для чего | Как подключено | Статус |
|---|---|---|---|
| **MAX Bot API** (`https://platform-api2.max.ru`) | ответы бота и уведомления | `GET /me` — ник бота для кнопок; `POST /messages?user_id=` — отправка; заголовок `Authorization: <токен>`. Собственный тонкий клиент на `fetch` ([`maxApi.ts`](apps/server/src/bot/maxApi.ts)), таймаут 10 с | реальная интеграция |
| **Вебхук MAX** | входящие события бота (`bot_started`, `message_created`) | `POST /bot/webhook`, секрет в заголовке `X-Max-Bot-Api-Secret`; при ошибке MAX повторяет доставку, обработчик идемпотентен | реальная интеграция |
| **MAX Bridge** | мини-приложение внутри MAX: данные запуска, номер телефона | `window.WebApp`; подпись `initData` проверяется на сервере на каждом запросе | реальная интеграция |
| **«Работа России»** (`opendata.trudvsem.ru`) | реальные места для студентов в регионах пилота | открытый API вакансий, импорт фоном при старте и раз в 6 часов; при недоступности — сохранённый снимок ([`import/`](apps/server/src/import/)) | реальная интеграция, только чтение |
| **GigaChat API** (Сбер, `gigachat.devices.sberbank.ru`) | ИИ-черновик карточки места: работодатель пишет задачу своими словами, модель предлагает заголовок, тег и навыки из справочника | токен OAuth по ключу `GIGACHAT_AUTH_KEY` (кэш до истечения), `POST /chat/completions`, таймаут 12 с, 10 черновиков в час на пользователя. Ответ проверяется по справочникам; без ключа или при ошибке — черновик по ключевым словам ([`ai/`](apps/server/src/ai/)). В подбор и процент совпадения ИИ не входит | реальная интеграция, по желанию |
| Источники мест (центр карьеры, «Факультетус», hh) | — | в MVP не подключены: места публикуют работодатели, плюс «Работа России» и тестовые данные | шаг масштабирования |

Всё, что проверено в документации MAX, со ссылками — [docs/05_max_platform.md](docs/05_max_platform.md).

### «Работа России»: что приходит и что будет, если сервис недоступен

- **Что берём.** Вакансии по запросам «стажёр» и «практикант» в Москве (пилот с РАНХиГС) и Татарстане (финал в Казани)
  из открытого API `GET https://opendata.trudvsem.ru/api/v1/vacancies/region/<код>`, все страницы до `meta.total`.
  В ленту попадают только места для студентов: без опыта или с опытом до года, с признаком студенческого места в
  названии («стажёр», «практикант», «младший», «помощник»…); продажа недвижимости «с обучением» — не берём.
  Город — из адреса вакансии; если его там нет, очное место не берём (кроме Москвы и других городов федерального
  значения): место в районе области не выдаём за место в столице региона. Удалёнка — по полю «тип занятости».
- **Как считается совпадение.** Навыки в вакансиях — свободный текст, поэтому название, требования и обязанности
  сопоставляются со справочником по словарю ([`skillMap.ts`](apps/server/src/import/skillMap.ts)). Вакансии, где не
  нашлось ни одного навыка из справочника, не берём: иначе совпадение было бы 100 % у всех. Теги задач
  («Маркетплейсы», «1С»…) ставятся по найденным навыкам, так что фильтр ленты находит и эти места; так же
  проставлены теги у тестовых мест.
- **Что храним.** Название, компанию, город, формат, обязанности и требования (до 1500 символов) и ссылку на оригинал.
  Телефоны, почту и контактное лицо **не храним** — ни из полей контактов, ни из текста обязанностей: студент
  откликается по ссылке на trudvsem.ru. В данных место помечено `source = 'trudvsem'`, это **не** тестовые данные.
- **Как часто.** При старте сервера (фоном, запуск не задерживает) и дальше раз в 6 часов. Пропавшие с сайта вакансии
  закрываются, но только если все запросы получены целиком.
- **Если сервис недоступен.** API отвечает медленно (12–15 с на страницу) и иногда обрывает ответ. На каждый запрос —
  таймаут 60 с, причины сбоев — в лог. Не ответила часть запросов — берём то, что пришло, ничего не закрываем.
  Не ответило ничего и в базе ещё нет мест из «Работа России» — заполняем её из сохранённого снимка
  ([`trudvsemSnapshot.ts`](apps/server/src/import/trudvsemSnapshot.ts), обновить: `npm run import:snapshot`). Если места
  уже есть, снимок их не трогает: не открывает закрытые и не затирает свежие данные старыми. Сценарий от сервиса не зависит.
- **Бот о местах из «Работа России» не уведомляет**: их много и они не от партнёров центра карьеры. Студент видит их в ленте.

## Работа с данными

**Что храним** (схема — [миграции](apps/server/src/db/migrations/)):

| Данные | Зачем | Кто видит |
|---|---|---|
| id пользователя MAX и имя; фамилия — только после согласия на обработку ПД; ник MAX не храним | вход без регистрации | сам пользователь |
| согласие на обработку ПД: дата и версия текста | обязательное условие до сбора анкеты | сам пользователь |
| телефон — только подтверждённый подписью MAX (`requestContact`) | связь после взаимного интереса | работодатель — **только после приглашения** |
| анкета студента: вуз, факультет, курс, направление, город, форматы, навыки из справочника (от 3), месяц практики (по желанию) | расчёт совпадения | работодатель — только у студентов, откликнувшихся на **его** место |
| профиль компании; места: тип, задача, навыки, теги задач, формат, город, сроки, оплата, число мест | публикация и подбор | все пользователи |
| отклики со статусом и процентом совпадения | воронка «интерес → приглашение» | студент и владелец стажировки |
| журнал уведомлений | повторы и отладка доставки | только сервер |

**Как защищаем:**
- каждый запрос к API подписан MAX (`initData`, HMAC-SHA256 токеном бота), подпись и срок проверяются на сервере;
- работодатель видит только свои места и их кандидатов, чужие — 404;
- фамилия и телефон студента раскрываются работодателю только после приглашения;
- в логах нет `initData`, телефонов, заголовков и тел запросов — в том числе в журнале ошибок прокси; логи Docker
  ротируются (10 МБ × 3);
- по номеру места (он виден в ссылке QR-плаката, `startapp=internship_<id>`) открывается только публичная карточка:
  задача, компания и город, условия, навыки. Без подписи MAX — 401. Кандидаты, приглашение и правка места — только
  владельцу, чужому — 404. Телефон и контактное лицо работодателя студент видит только после приглашения, фамилию
  и телефон студента работодатель — тоже только после приглашения и только у откликнувшихся на его место;
- у работодателя не больше 20 открытых мест; некорректные запросы получают 4xx, а не 500;
- лимит запросов к API, CORS только для домена мини-приложения, секреты только в `.env`, история git проверяется
  на секреты в CI (gitleaks);
- БД не доступна из сети, в проде наружу открыт только HTTPS.

Тестовые записи помечены `is_demo = true` (места — ещё `source = 'demo'`).

### Метрики пилота

Метрики эффекта из [docs/03_product.md](docs/03_product.md) считаются по базе одной командой — без тестовых
записей и без персональных данных, только агрегаты:

```bash
docker compose exec meb-server npm run metrics -- --from 2026-10-01 --to 2026-12-31
```

Даты включительно, по Москве; без них — за всё время. При разработке — `npm run metrics:dev` в `apps/server`.

| Метрика | Как считается |
|---|---|
| места, опубликованные работодателями | `internships`, `source = 'employer'`, без импорта из «Работа России» |
| публикация → первый подходящий отклик | медиана `interests.interested_at − internships.created_at` при совпадении ≥ 60 % и доля мест, где отклик пришёл не позже 2 рабочих дней (выходные по Москве не считаются, праздники — считаются) |
| доля «Интересно» с совпадением ≥ 70 % | по `interests.interested_at` за период |
| «Интересно», которые работодатель не отклонил | доля откликов без статуса `declined` |
| ответ работодателя на отклик | медиана от «Интересно» до приглашения или отказа; время решения — последнее изменение отклика |
| анкета → первое «Интересно» | студенты, заполнившие анкету за период, и сколько из них хоть раз нажали «Интересно» |
| приглашения | `interests.status = 'invited'` по времени последнего изменения отклика — отдельного времени приглашения в базе нет |
| кого приглашают по проценту | «Интересно» за период по полосам совпадения 80+ / 70–79 / 60–69 / ниже 60 % и сколько из них приглашены — по нему после пилота подбираются порог и веса 70/30 |

Главная метрика в продукте — время от *начала заполнения* карточки, но на сервер форма уходит целиком, поэтому
команда считает от публикации. Время сборки карточки показывается работодателю на экране «Место опубликовано».

| отклики со статусами «интересно», «приглашён», «отказ» | 68 |

Навыки студентов подобраны так, что у каждой стажировки есть подходящие кандидаты с совпадением от 80 %,
60–79 % и ниже 60 %, а часть студентов не проходит фильтры по городу или формату. Это проверяет тест
[`demo.test.ts`](apps/server/src/seed/demo.test.ts). Процент в откликах считает тот же модуль `matching`.

**Демо-отклики на стажировку проверяющего.** Проверяющий один, поэтому в демо-режиме на стажировку, которую он
опубликует в роли работодателя, сразу откликаются до 5 подходящих тестовых студентов с совпадением от порога:
до трёх сильных (от 80 %) и до двух, у которых чего-то не хватает, — чтобы была видна расшифровка. Среди тестовых
студентов есть жители Казани и Петербурга, поэтому очная стажировка не только в Москве тоже получит кандидатов.
Так список кандидатов не пустой, и сценарий можно пройти до приглашения. Если проверяющий выберет в форме тег
«Маркетплейсы», «Сайт», «Таблицы и аналитика», «Соцсети и реклама» или «1С» и оставит навыки, которые тег подставил —
два обязательных и остальные желательные (Москва, гибрид), откликнутся не меньше четырёх студентов, из них двое — от 80 %; это тоже проверяет `demo.test.ts`.
Бот присылает проверяющему одно сообщение: «откликнулись N тестовых студентов».

**Приглашение от демо-компании.** Обратная сторона — путь студента: за демо-компании войти нельзя, поэтому на
«Интересно» к открытому демо-месту с совпадением от 70 % демо-компания через 20 секунд приглашает сама. Бот
присылает «Тестовое приглашение» с вымышленным контактом, в приложении открывается «Это тандем!». Не чаще одного
такого приглашения студенту в сутки; отклики, сделанные за 10 минут до рестарта сервера, приглашаются после старта.
В метрики пилота отклики на демо-места не попадают.

**Как тестовые данные помечены:**
- в БД: `is_demo = true` у пользователей, анкет, компаний, стажировок и откликов; у стажировок ещё `source = 'demo'`;
- id пользователей MAX отрицательные — не пересекаются с настоящими, бот им не пишет;
- телефоны вида `+7 000 000-XX-XX` — кода 000 в российской нумерации нет;
- в интерфейсе — пометка «тестовые данные».

## Известные ограничения

Продукт:

- Эффект и метрики (время до первого подходящего отклика, доля откликов с высоким совпадением) — гипотезы.
  Проверяем их в пилоте. Договорённости о пилоте с центром карьеры РАНХиГС пока нет, мы его предлагаем.
- Юридические тексты в «О сервисе» — черновики для хакатона. Реквизиты оператора не указаны.
- Бот выдан организаторами хакатона, он один на все среды.
- Процент совпадения считается по навыкам, которые студент отметил сам; навыки не проверяются.
- Место может опубликовать любой пользователь MAX. В пилоте места публикуют партнёры центра карьеры; у работодателя
  не больше 20 открытых мест, телефон подтверждается через MAX.
- MAX с 03.06.2026 нет в App Store, на iPhone push-уведомления от MAX не приходят: уведомления бота студент с iPhone
  увидит, только открыв MAX. Всё остальное работает в веб-версии MAX и на Android.
- С 01.03.2027 стажировка по закону от 26.07.2026 — срочный трудовой договор с наставником. Чек-лист «Следующие
  шаги» для стажировки описывает общий порядок и будет обновлён под закон.
- Договор о практике в MVP не оформляется: его можно оформить на «Работе России» в сервисе «Стажировки и практики»
  или напрямую с вузом.

Подбор, бот и данные:

- Совпадение считается по справочнику навыков, а не по тексту резюме или описания стажировки.
- Справочник навыков — 84 позиции под направления РАНХиГС и задачи малого бизнеса; для другого вуза его нужно дополнить.
- Компании, стажировки и студенты в демо — тестовые данные, подготовленные командой.
- Интеграций с «Факультетусом», hh и базой центра карьеры в MVP нет.
- Бот не ведёт диалог: всё действие — в мини-приложении, бот приветствует и присылает уведомления.
- Чек-лист следующих шагов — общий; документы для практики у разных вузов разные, в пилоте его уточняет центр карьеры.

## Остановка и повторный запуск

```bash
docker compose down        # остановить, данные БД сохраняются в томе db-data
docker compose up          # запустить снова
docker compose down -v     # остановить и удалить данные (чистый старт)
```

Поменяли `POSTGRES_PASSWORD` после первого запуска — база в томе осталась со старым паролем: `docker compose down -v`
и запустить заново.
