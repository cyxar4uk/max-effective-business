### 2. Экраны по сценарию

- [ ] Главный: выбор или переключение роли. Один проверяющий должен пройти обе роли.
- [ ] Студент: согласие на ПД → номер через `requestContact` → анкета (навыки из справочника, поиск по списку) →
      лента карточек (свайп на телефоне, кнопки «Интересно» и «Пропустить» всегда видны) → карточка стажировки с
      процентом и расшифровкой → «Мои отклики» со статусами.
- [ ] Работодатель: профиль компании → форма стажировки (обязательные и желательные навыки, проверка полей, черновик
      не теряется при ошибке) → «Мои стажировки» → список кандидатов по убыванию совпадения, раскрытие расшифровки, «Пригласить» или «Отказать».
- [ ] «О сервисе»: назначение, пометка «данные в демо тестовые», пользовательское соглашение, политика, согласие на
      обработку ПД, реквизиты и поддержка (тексты даёт Артём).
- [ ] Метка «демо» на тестовых записях.

### 3. Состояния — это отдельный пункт критерия UX

- [ ] Каждый экран: загрузка (скелетон), пусто (с действием: «Заполните анкету», «Создайте стажировку»), ошибка
      (что случилось и что делать + «Повторить»), успех (короткое подтверждение, тактильный отклик).
- [ ] Никаких тупиков: после каждого действия понятно, куда дальше.
- [ ] Работает в **мобильной и веб-версии MAX**: адаптивная вёрстка, свайп не единственный способ действия.

### 4. Режим ярмарки — платформенный бонус (Should, после Must)

- [ ] У работодателя на стажировке кнопка «QR для стенда»: QR с диплинком `https://max.ru/<ник_бота>?startapp=internship_<id>`

- [ ] У студента кнопка «Сканировать QR» → `openCodeReader()` → разбор диплинка → карточка стажировки → «Интересно».
      В веб-версии сканер может работать через файл, проверить.
- [ ] «Поделиться стажировкой» через `shareMaxContent`.
