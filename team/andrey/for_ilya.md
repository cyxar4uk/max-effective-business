# Илье от Андрея: что нужно по серверу, API и деплою

Обновлено: 28.09.2026, вечер. По порядку важности. Вопросы — в личку или комментарием в PR.

## 1. Сервер (28.09 утром)

- SSH-доступ для Андрея: юзер в группе `docker` + его публичный ключ (скинул в личку) и каталог под код:
  `sudo install -d -o <юзер> /opt/max-effective-business`.
- **Deploy key в репозиторий** — добавить можешь только ты как владелец: GitHub → репозиторий → Settings →
  Deploy keys → Add, **без** «Allow write access». Ключ Андрей создаст на сервере и пришлёт. Без него
  `scripts/deploy.sh` не сможет забирать код: репозиторий приватный.
- Что стоит как прокси: nginx или Caddy, в Docker или на хосте.
- Сколько свободной памяти (нам ~500 МБ) и есть ли Docker Compose v2.24+.
- Поддомен под нас с A-записью на этот сервер, например `career.<твой домен>`.

Твою миниапку не трогаем: у нас свои контейнеры, сеть и тома, из общего — только блок в прокси. Всё готово:
[docs/deploy.md](../../docs/deploy.md), раздел «Если на сервере уже есть nginx или Caddy».

## 2. Новое в контракте с 28.09 (решения Артёма)

Всё уже в `main`, подробно — [docs/api.md](../../docs/api.md).

- **Форма места** (`POST /api/internships`), обязательно: `type` (`practice` / `internship` / `part_time`), `title`
  (задача), `requiredSkills` (≥ 1), `format`, `city` (кроме `remote`), `startsOn`, `endsOn`, `paid` (да/нет), `slots`.
  По желанию: `description`, `niceSkills`, `tags` (0–3), `salary` (₽/мес, только при `paid: true`). Ответ — `201`.
- **Теги задач**: `GET /api/tags` → `{ items: [{ code, name, skills }] }`. Выбрал тег — подставь его `skills` в форму
  (работодатель правит). Лента студента фильтруется: `GET /api/student/feed?tags=website,one_c`.
- **Анкета студента**: минимум **3 навыка**; `practiceMonth` (`ГГГГ-ММ`) по желанию.
- У места в ответах теперь `type`, `paid`, `salary`, `tags`; у старых и демо-мест `paid` и сроки могут быть `null`.
- `/api/skills` отдаёт группы в порядке Артёма («Маркетплейсы» вторые), не сортируй их сам.
- Проверки формы идут по этапам (сначала поля, потом правила между полями, потом справочники), поэтому
  город для очного, даты и «сумма только при оплате» лучше проверять и в форме.

## 3. Мини-приложение ↔ сервер

Контракт — [docs/api.md](../../docs/api.md). Главное:

- Базовый адрес API — относительный `/api`: мы на одном домене с мини-приложением.
- В **каждый** запрос заголовок `X-Max-Init-Data` = `window.WebApp.initData` — строка как есть, **не** `initDataUnsafe`.
  Без него 401.
- Ошибки всегда `{ error: { code, message, fields? } }`. `message` можно показывать как есть, `fields` — ошибки по
  полям формы.
- Онбординг по шагам:
  1. `GET /api/me` → `consent`, `hasPhone`, `roles: { student, employer }`;
  2. согласие → `POST /api/me/consent` с `{ "version": "2026-09-27" }` — версия строго эта, иначе 400;
  3. телефон → `POST /api/me/phone` с **ровно тем объектом**, что вернул `await WebApp.requestContact()`
     (`{ phone, authDate, hash }`), сервер проверяет подпись MAX. Отказ пользователя — просто не вызываешь;
  4. справочник — `GET /api/skills`. Навыки везде передаются кодами (`excel`, `sql`), названия бери отсюда;
  5. студент — `PUT /api/student/profile`, работодатель — `PUT /api/employer/profile`. До согласия оба → 403.
- Студент: `GET /api/student/feed` (лента), `GET /api/internships/:id` (карточка с `match` и `myInterest`),
  `POST /api/internships/:id/interest` с `{ "action": "interested" | "skipped" }`, `GET /api/student/interests`
  («Мои отклики»; при `invited` там контакт работодателя).
- Работодатель: `POST /api/internships`, `GET /api/employer/internships` (со счётчиками), `PATCH /api/internships/:id`
  (изменить или `status: "closed"`), `GET /api/internships/:id/candidates` (по убыванию совпадения),
  `POST …/candidates/:studentId/invite` и `…/decline`.
- `match = { score, mustMatched, mustMissing, niceMatched, niceMissing }` — коды навыков, расшифровку рисуешь сам.
- 409 — недопустимое действие (уже приглашён, стажировка закрыта): показать `message`.
- Телефон и фамилия студента приходят работодателю только после «Пригласить», до этого `null` — так задумано.

## 4. Параметры запуска от бота Тимура

`window.WebApp.initDataUnsafe.start_param`:

| Значение | Что открыть |
|---|---|
| `student` | роль студента |
| `employer` | роль работодателя |
| `internship_<id>` | карточку стажировки; если `isOwner: true` в ответе — сразу список кандидатов (так открывается кнопка «Кандидаты» из уведомления работодателю) |

## 5. Что должно быть в интерфейсе

- Плашка «тестовые данные» у стажировок и кандидатов с `isDemo: true` — это обещано жюри в README.
- Подсказка «Чтобы получать уведомления, запустите бота» со ссылкой `https://max.ru/<ник_бота>?start=`: кто открыл
  мини-приложение по ссылке, мог не нажать «Начать» у бота.
- Для модерации MAX: `WebApp.ready()`, `BackButton`, страница «О сервисе» со ссылками на соглашение, политику,
  реквизиты и поддержку.
- Пустые состояния, загрузка и ошибки на каждом экране. Работодателю на пустом списке кандидатов — подсказка:
  очная стажировка в городе, где нет демо-студентов, может остаться без откликов.
- Переключатель ролей на главном: жюри проходит обе роли одним аккаунтом.

## 6. Разработка вне MAX

```bash
cd apps/server
NODE_ENV=development npm run dev:init-data -- 100001 Студент                 # строка для X-Max-Init-Data, живёт сутки
NODE_ENV=development npm run dev:init-data -- 100002 Работодатель            # второй пользователь
NODE_ENV=development npm run dev:init-data -- 100001 Студент internship_5    # со start_param
NODE_ENV=development npm run dev:contact -- 100001 +79990000000              # тело для POST /api/me/phone
```

- Нужен тот же `MAX_BOT_TOKEN`, что у сервера (в `.env`, значение — у Андрея в личке).
- Сервер через `docker compose`, а ты с `localhost:5173` — поставь в `.env` `MINIAPP_URL=http://localhost:5173`,
  иначе CORS.

## 7. Docker для мини-приложения

С нашей стороны всё готово и проверено на всех трёх вариантах запуска — ветка `andrey/miniapp-compose`: сервис
`miniapp` в compose, маршрут `/` в Caddy и примерах nginx, smoke и CI. Смёржу сразу после твоего `Dockerfile`.
От тебя в `apps/miniapp/`:

- `Dockerfile`, многоэтапный: сборка на `node:24.21.0-alpine3.24` через `npm ci` и `npm run build` (сборка в `dist/`),
  раздача статики nginx **на alpine** с фиксированной версией, например `nginx:1.30.5-alpine3.24-slim`, **порт 80**.
  Alpine важен: healthcheck в compose ходит через `wget`, в debian-образе nginx его нет.
- Конфиг nginx: неизвестные пути → `index.html` (`try_files $uri /index.html;`), если роутер на History API, — иначе
  перезагрузка экрана внутри MAX даст 404; `index.html` с `Cache-Control: no-cache`, чтобы после выкатки MAX сразу
  брал новую версию. `/api/*` проксировать не нужно: в проде его забирает прокси до твоего контейнера.
- `.dockerignore` (`node_modules`, `dist`, `.env*`) и `package-lock.json` в репозитории.
- Сборка всего стека должна уложиться в 5 минут; сейчас сервер + БД — около 30 секунд.
