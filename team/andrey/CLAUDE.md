## Архитектура (предложение, окончательно решаешь ты)

```
MAX (клиент) ──> мини-приложение (статика, nginx) ──HTTPS──> server /api ──> PostgreSQL
MAX Bot API  <──> server: модуль bot (вебхук в проде)         │
                        server: matching, import, seed ◀──────┘ внутренние события
```

- **Один процесс сервера** обслуживает и API мини-приложения, и бота. Меньше частей — выше стабильность.
- Node.js 24 + TypeScript (Node 20 снят с поддержки, см. `docs/decisions.md`). HTTP-фреймворк и ORM — то, что команда знает. В команде знают Express и TypeORM;
  если есть более быстрый для тебя вариант — одна строка в `docs/decisions.md`.
- Внутренние события: `internship.created`, `interest.created`, `interest.invited`. Ты публикуешь, модуль бота Тимура
  подписывается. Бот ничего не знает про HTTP, API ничего не знает про MAX Bot API.
- Структура:
  ```
  apps/server/src/
    index.ts  config.ts  events.ts
    api/      маршруты и обработчики          (Андрей)
    auth/     проверка initData, текущий пользователь (Андрей)
    db/       схема, миграции, репозитории     (Андрей)
    bot/      обработчики, очередь уведомлений (Тимур)
    matching/ расчёт совпадения                (Тимур)
    import/   «Работа России»                  (Тимур)
    seed/     тестовые данные                  (Тимур)
  ```

## Собственный API — не заявляем

Кейс требует от «решений с собственным API» HTTPS-адрес, OpenAPI, `DATA-API.yaml` и тестовые учётки, и эти
проверки влияют на баллы. Наш сервер — внутренний бэкенд мини-приложения, без подписанного `initData` его не вызвать.
Предложение: **публичный API не заявлять**, `docs/api.md` вести как внутренний контракт. Артём подтверждает это у
организаторов. Если скажут заявлять — это отдельная задача на тебя.

## Черновик контракта (перенести в `docs/api.md` и доработать)

Все запросы, кроме `health`, — с заголовком `X-Max-Init-Data`. Ошибка:
`{ "error": { "code": "VALIDATION_ERROR", "message": "Понятный текст", "fields": { "title": "Обязательное поле" } } }`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | проверка живости, без авторизации |
| GET | `/api/me` | пользователь, какие профили есть (студент, работодатель), дано ли согласие |
| POST | `/api/me/consent` | сохранить согласие на обработку ПД |
| POST | `/api/me/phone` | сохранить телефон из `requestContact` (формат уточнить по документации MAX вместе с Ильёй) |
| GET | `/api/skills` | справочник навыков по группам |
| GET · PUT | `/api/student/profile` | анкета студента |
| GET | `/api/student/feed` | подходящие стажировки, ещё не просмотренные, с `match` |
| GET | `/api/internships/:id` | стажировка; для студента — с `match` |
| POST | `/api/internships/:id/interest` | `{ "action": "interested" \| "skipped" }` |
| GET | `/api/student/interests` | мои отклики со статусами |
| GET · PUT | `/api/employer/profile` | профиль компании |
| POST | `/api/internships` | создать стажировку → событие `internship.created` |
| GET | `/api/employer/internships` | мои стажировки со счётчиками откликов |
| PATCH | `/api/internships/:id` | закрыть или изменить |
| GET | `/api/internships/:id/candidates` | заинтересованные студенты по убыванию `match.score` |
| POST | `/api/internships/:id/candidates/:studentId/invite` | пригласить → событие `interest.invited` |
| POST | `/api/internships/:id/candidates/:studentId/decline` | отказать |

Формат `match` (согласовать с Тимуром):
`{ "score": 78, "mustMatched": ["Excel"], "mustMissing": ["SQL"], "niceMatched": ["Power BI"], "niceMissing": [] }`.
