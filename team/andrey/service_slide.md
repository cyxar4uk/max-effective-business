# Первый служебный слайд

Требование кейса: ссылка на бота, репозиторий и hash, тестовые логины, значения env для проверки, краткий сценарий.
Всё заполнено, кроме hash: его вписываем после заморозки 30.09 18:00 из `scripts/freeze-check.sh` — тот же, что в
форме сдачи.

---

**Бот в MAX:** https://max.ru/t373_hakaton_max_bot (выдан организаторами; в MAX называется «Хакатон МАХ 373»)
**Мини-приложение:** https://tandem.anyway-community.ru — открывается кнопками бота
**Репозиторий:** https://github.com/cyxar4uk/max-effective-business · commit `…` (= hash в форме сдачи; на проде он же)

**Как проверить за 5–7 минут** — одним аккаунтом MAX, роли переключаются в приложении:
1. Бот → «Начать» → «Я работодатель» → согласие → профиль компании → форма места (8 шагов) → «Опубликовать».
2. «Смотреть кандидатов»: тестовые студенты откликнулись сразу, процент совпадения и расшифровка.
3. «Сменить роль» → «Я студент» → анкета → в колоде «Ваше место» → «Интересно».
4. Снова работодатель → своё место → «Пригласить» → «Это тандем!»: оба получают контакты, бот присылает чек-лист.

Подробно, с ожидаемым результатом каждого шага, — README, «Пошаговый сценарий проверки». Тестовые данные помечены
«тестовые данные». С 22:00 до 9:00 МСК бот откладывает уведомления до утра, в мини-приложении всё видно сразу.

**Тестовые логины:** не нужны — вход через аккаунт MAX проверяющего.

**Запуск у себя:** `cp .env.example .env` → `MAX_BOT_TOKEN=local-check` (любая непустая строка), `POSTGRES_PASSWORD` —
любой → `docker compose up --build` (с нуля 38 с вместе с мини-приложением, замер в CI). API, мини-приложение на
`:8080` и тестовые данные работают; бот локально на `/start` не отвечает — для проверки в MAX используйте бота по
ссылке выше, токен не нужен.

**Внешние сервисы:** MAX Bot API и MAX Bridge (в Docker не поднимаются), «Работа России» (открытый API вакансий,
при недоступности — сохранённый снимок).
