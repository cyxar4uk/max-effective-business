# Claude Тимура: бот, расчёт совпадения, тестовые данные, импорт

Ты помогаешь **Тимуру** — бэкенд-разработчику команды. На нём всё, что превращает базу стажировок в продукт:
бот, который лично доставляет стажировку нужному студенту, расчёт совпадения с расшифровкой и данные, на которых
жюри пройдёт сценарий.

Сначала прочитай общий `CLAUDE.md` в корне, затем `docs/03_product.md` (разделы «Основной сценарий», «Бот»,
«Расчёт совпадения», «Данные»), `docs/05_max_platform.md` (раздел Bot API) и `docs/04_criteria_map.md` (строки с Тимуром).

## Откуда задачи

Задачи ставит Артём в GitHub Issues. В начале каждой сессии: `git pull`, затем `gh issue list --assignee @me --state open`,
и работай по ним в порядке приоритета. Стартовый план ниже действует, пока Issues не заведены. Если задача в Issues
с ним расходится, права задача. Спеки фич — в `docs/features/`. Как брать задачу, задавать вопросы и закрывать —
раздел «Задачи» в общем `CLAUDE.md`.

## Твоя зона

- `apps/server/src/bot/` — бот: обработчики, кнопки, очередь уведомлений.
- `apps/server/src/matching/` — расчёт совпадения.
- `apps/server/src/import/` — импорт из «Работа России».
- `apps/server/src/seed/` — тестовые данные и справочник навыков.
- Каркас сервера, API, аутентификация, БД и Docker — зона **Андрея**. Нужен репозиторий, событие или поле в БД — договаривайся с ним.

## За какие критерии отвечаешь

По `docs/04_criteria_map.md`: работоспособность (бот и уведомления — часть основного сценария), внешние интеграции
(MAX Bot API, «Работа России»), стабильность (повторы, лимиты, идемпотентность), архитектура (чистый расчёт
совпадения с тестами), платформенный бонус (вместе с Ильёй), разделы README про бота, подбор и тестовые данные.

### 1. Расчёт совпадения — первым, он нужен всем

- [ ] Чистые функции без БД и сети: вход — навыки и параметры студента, требования стажировки; выход —
      `{ score, mustMatched, mustMissing, niceMatched, niceMissing }` плюс признак, пройдены ли жёсткие фильтры.
- [ ] Правила из `docs/03_product.md`: жёсткие фильтры (формат; город для очных); `70 % × доля закрытых
      обязательных + 30 % × доля закрытых желательных`; без желательных — только обязательные; округление до целых.
      Порог уведомления 60 % в конфиге.
- [ ] Юнит-тесты на крайние случаи: нет обязательных, нет желательных, всё закрыто, ничего не закрыто, не прошёл фильтр по формату или городу.

### 2. Бот

- [ ] `/start` → приветствие и две кнопки открытия мини-приложения: «Я студент» (`startapp=student`) и
      «Я работодатель» (`startapp=employer`). Короткий текст о том, что это и что данные в демо тестовые.
- [ ] Прочие сообщения → подсказка и те же кнопки. Тупиков в диалоге быть не должно.
- [ ] Уведомления по событиям:
  - `internship.created` → всем студентам с совпадением ≥ порога: карточка (название, компания, процент,
    2–3 совпавших навыка) + кнопка «Открыть» (`startapp=internship_<id>`);
  - `interest.created` со статусом `interested` → работодателю: «Новый заинтересованный студент, совпадение N %» + кнопка к списку кандидатов;
  - `interest.invited` → студенту: приглашение, контакт работодателя, **чек-лист следующих шагов**;
    работодателю — контакт студента.
- [ ] Очередь отправки: не больше 2 сообщений в секунду в один диалог и с запасом по общему лимиту около 30 запросов
      в секунду; повтор с паузой при временной ошибке; каждая отправка — запись в `notifications` (статус, ошибка).
      **Ошибка отправки не должна ронять запрос пользователя.**
- [ ] Режим получения событий: вебхук в проде (поднимает Андрей), long polling — только если есть отдельный бот для разработки.
      С одним токеном оба режима одновременно не работают.
- [ ] Тексты бота согласовать с Артёмом. Чек-лист следующих шагов — по ответу центра карьеры о документах для стажировки и практики.
